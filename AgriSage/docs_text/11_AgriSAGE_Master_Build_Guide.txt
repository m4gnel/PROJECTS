1.4 The Golden Rule of AI-Assisted Building
▶ ONE TASK PER AI SESSION. Give one task. Verify the output. Then give the next task. Never give 5 tasks at once.
▶ ALWAYS VERIFY before moving on. Run the code. Check it works. Fix errors before next task.
▶ WHEN AI MAKES AN ERROR — do not start over. Give a correction prompt. See Part 4.
▶ NEVER let AI skip exit criteria. If Phase 1 exit criteria are not all passing, fix them before Phase 2.
▶ COPY PROMPTS EXACTLY from this guide. These prompts are tested and precise.

PART 3: HOW TO HANDLE ERRORS
3.1 When AI Produces Wrong Code
Do NOT start over. Give a targeted correction prompt:
[Context: Building Agri-SAGE. Previous task: [describe task]. Problem: [describe exactly what is wrong].
Fix ONLY this specific issue: [describe issue].
Do not change anything else. Show only the changed section of the file.
Example:
Context: Building Agri-SAGE vision agent. Problem: The VisionAgent is calling the LLM to get disease names instead of using disease_classes.json.
Fix ONLY this: Replace the LLM call with loading class names from backend/data/disease_classes.json at initialization. Do not change anything else in vision.py.

AI models sometimes forget earlier decisions. Use this reset prompt:
Agri-SAGE context refresh:

- Python 3.11, SQLAlchemy 2.0 async
- Android: Kotlin + Jetpack Compose + Room + WorkManager
- Primary language: Malayalam for farmers
- CRITICAL: LLM only synthesizes — never invents facts, chemicals, or scheme eligibility
- All simulation outputs labelled 'modelled estimate'
- Confidence states: CONFIRMED/LIKELY/POSSIBLE/UNCERTAIN/INSUFFICIENT_DATA/CONFLICTING_EVIDENCE/OUT_OF_SCOPE
Now: [your task]

STOP. You are adding [feature name] which is NOT in scope for this phase.

Remove [feature name] and implement only what was asked: [restate original task].

Fix only the implementation code to make this test pass.
