3.4 Handling Merge Conflicts
A merge conflict happens when two members edit the same file. Here is how to fix it:
# Git will show: CONFLICT (content): Merge conflict in backend/main.py
# Open the conflicted file in VSCode
# You will see markers like this:
<<<<<<< HEAD
your version of the code
=======
their version of the code
>>>>>>> dev/m1-backend
# In VSCode: click 'Accept Current Change' or 'Accept Incoming Change'
# OR manually edit to keep the correct version
# Then:
git add backend/main.py
git commit -m 'Resolve merge conflict in main.py'
⚠ If you are unsure which version to keep in a conflict — do NOT guess. Message the other person on WhatsApp and resolve together. A wrong merge can break the project for everyone.

4.2 How to Use Cline Effectively — For Beginners
Cline is your main coding tool. Here is how to use it step by step:
Step 1: Click the Cline robot icon in the left sidebar of VSCode
Step 2: A chat panel opens on the right side
Step 3: At the top of the chat, type @ to attach documents
         Example: @docs/05_BackendSchema.docx
         This tells Cline to read that document before answering
Step 4: After the @ mention, paste your prompt from the build guide
Step 5: Press Enter — Cline reads the document and writes code
Step 6: Cline will ask 'Do you want to create this file?' → Click Yes
Step 7: The file appears in your project automatically
Step 8: Review what Cline created — read through it
Step 9: If something looks wrong, use the correction prompt from build guide Part 9
✓ Cline with Gemini 1.5 Pro has a 1 million token context window. This means it can read MULTIPLE documents at once. For complex tasks, attach 2-3 documents. For simple tasks, attach just 1.
⚠ Never blindly run code you have not read. Even if Cline writes it, you must read it. If you do not understand something, ask Cline: 'Explain what this function does in simple terms.'

6.2 The 3-Slide Presentation
Before the live demo, show 3 slides. Keep it under 3 minutes.
Slide 1: What is Agri-SAGE? — One sentence description. Show the problem (farmer without agronomist). Show the solution (Agri-SAGE). List 3 key features.
Slide 2: Architecture — Simple diagram showing: Farmer Phone → AI Agents → Knowledge Base + Simulation → Advisory. Show it is offline-capable. Show Malayalam support.
Slide 3: Progress by October 1st — Checklist of what is working. Roadmap of what comes next. Launch plan.
⚠ Do not show code to HR. Do not show technical architecture details. Show the app working. Show a farmer getting an advisory. That is what matters to HR.
6.3 If Something Breaks During Demo
Problem
Backup Plan
Internet goes down
Turn on airplane mode — show offline advisory still works. This is actually a feature demonstration.
Backend server is down
Use offline mode exclusively. Show all offline features. Explain server will be fixed after demo.
Vision model gives wrong result
Show the confidence indicator is low. Explain the system says 'insufficient data' — this is correct behavior, not a bug.
Android app crashes
Have a second phone ready with app installed. Or show screenshots of working app.
Team member absent
Each member must brief one other member on their part. No single point of failure.
