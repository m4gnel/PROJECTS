CRITICAL RULES FOR EVERY LLM CALL
⚠ These rules apply to EVERY LLM interaction in Agri-SAGE. Violating any of these rules creates safety risks for farmers.
Rule
Statement
RULE-LLM-001
The LLM NEVER invents agricultural facts. It synthesizes ONLY from the evidence bundle and retrieved knowledge chunks provided in the prompt.
RULE-LLM-002
The LLM NEVER names a chemical product, pesticide, or fertilizer that does not appear in the retrieved knowledge chunks or CIB&RC data provided in the prompt.
RULE-LLM-003
The LLM NEVER states a yield number, profit figure, or cost estimate without labelling it 'modelled estimate' — these come from simulation output, not LLM knowledge.
RULE-LLM-004
The LLM NEVER recommends treatment when confidence_state is UNCERTAIN, INSUFFICIENT_DATA, or CONFLICTING_EVIDENCE. It requests more information instead.
RULE-LLM-005
The LLM NEVER claims a farmer is eligible for a government scheme. It says 'you appear to meet the listed criteria — final eligibility determined by the concerned authority'.
RULE-LLM-006
All LLM output is parsed as JSON against a Pydantic schema before use. Raw LLM text is NEVER passed directly to the farmer response.
RULE-LLM-007
If the LLM returns invalid JSON, retry once with 'Output only valid JSON.' appended. If second attempt fails, use the safe fallback template — do not show LLM output.
RULE-LLM-008
User text (problem_description, voice transcript) is NEVER inserted into the LLM system prompt. It is passed as structured data in the user message only.

5.1 Qwen3 API Call Wrapper
# backend/services/llm_service.py
import httpx
import json
from typing import Optional, Type
from pydantic import BaseModel
class LLMService:
    def __init__(self, model: str = 'qwen3-7b', base_url: str = 'http://localhost:11434'):
        self.model = model
        self.base_url = base_url  # Ollama local server
        self.client = httpx.AsyncClient(timeout=30.0)
    async def generate(
        self,
        system_prompt: str,
        user_prompt: str,
        temperature: float = 0.2,
        max_tokens: int = 1500,
        output_schema: Optional[Type[BaseModel]] = None,
    ) -> dict:
        payload = {
            'model': self.model,
            'messages': [
                {'role': 'system', 'content': system_prompt},
                {'role': 'user', 'content': user_prompt},
            ],
            'temperature': temperature,
            'max_tokens': max_tokens,
            'stream': False,
        }
        response = await self.client.post(f'{self.base_url}/api/chat', json=payload)
        response.raise_for_status()
        content = response.json()['message']['content']
        # Parse JSON — retry once if invalid
        for attempt in range(2):
            try:
                # Strip markdown code fences if model adds them
                clean = content.strip()
                if clean.startswith('```'):
                    clean = clean.split('```')[1]
                    if clean.startswith('json'):
                        clean = clean[4:]
                result = json.loads(clean)
                if output_schema:
                    return output_schema(**result).model_dump()
                return result
            except (json.JSONDecodeError, ValueError) as e:
                if attempt == 0:
                    user_prompt += '\n\nIMPORTANT: Output ONLY valid JSON. No other text.'
                    response = await self.client.post(f'{self.base_url}/api/chat', json=payload)
                    content = response.json()['message']['content']
                else:
                    logger.error('llm_json_parse_failed', error=str(e))
                    return None  # Caller uses fallback

5.3 Embedding Model Setup
# backend/services/embedding_service.py
from sentence_transformers import SentenceTransformer
class EmbeddingService:
    _instance = None
    @classmethod
    def get_instance(cls):
        if cls._instance is None:
            # multilingual-e5-large — MIT license — free for commercial use
            cls._instance = SentenceTransformer('intfloat/multilingual-e5-large')
        return cls._instance
    def embed_query(self, text: str) -> list[float]:
        # REQUIRED: 'query: ' prefix for e5 models
        return self.get_instance().encode(f'query: {text}').tolist()
    def embed_passage(self, text: str) -> list[float]:
        # REQUIRED: 'passage: ' prefix for e5 models
        return self.get_instance().encode(f'passage: {text}').tolist()
    def embed_batch(self, texts: list[str], is_query: bool = False) -> list[list[float]]:
        prefix = 'query: ' if is_query else 'passage: '
        prefixed = [f'{prefix}{t}' for t in texts]
        return self.get_instance().encode(prefixed).tolist()
⚠ Always use 'query: ' prefix for search queries and 'passage: ' prefix for documents. Omitting these prefixes degrades retrieval quality by 15-25% for multilingual-e5-large. This is a model requirement, not optional.
6. CRITIC AGENT — COMPLETE LOGIC
6.1 Confidence State Assignment Rules
The Critic Agent is entirely rule-based — NO LLM. These rules are deterministic.
Condition
Confidence State
Action
All evidence aligns: vision confidence > 0.80 AND weather supports AND stage matches AND Tier 1 knowledge found
CONFIRMED
Allow treatment recommendation. Set run_simulation=True.
Vision confidence 0.60-0.80 AND most evidence supports AND no major conflicts
LIKELY
Allow treatment recommendation with caveats. Set run_simulation=True if confidence > 0.65.
Vision confidence 0.40-0.60 OR minor weather conflict OR no Tier 1 knowledge
POSSIBLE
Allow conservative recommendation. Flag missing data. run_simulation=False.
Vision confidence < 0.40 OR multiple evidence conflicts OR poor image quality score < 0.4
UNCERTAIN
Do NOT recommend treatment. Request better image or field inspection.
Image OOD detected OR crop not in supported list OR critical data missing
INSUFFICIENT_DATA
Do NOT recommend treatment. Request specific missing information.
Vision says X, weather strongly contradicts X, AND crop stage says X uncommon
CONFLICTING_EVIDENCE
Do NOT recommend treatment. Explain the conflict. Suggest expert review.
Crop or region not in supported scope
OUT_OF_SCOPE
Return message listing supported crops/regions. Offer to notify when supported.

# scripts/evaluate_retrieval.py
# Run monthly to ensure RAG quality is maintained
BENCHMARK_QUERIES = [
    {
        'query_text': 'rice blast disease treatment Kerala tillering stage',
        'expected_tier': 1,
        'expected_crop': 'rice',
        'expected_topic': 'blast_disease',
        'minimum_recall_at_5': 0.80,
    },
    {
        'query_text': 'banana bunchy top virus symptoms management',
        'expected_tier': 1,
        'expected_crop': 'banana',
        'minimum_recall_at_5': 0.75,
    },
    # Add minimum 20 queries covering all crops and key diseases
]
def evaluate_retrieval(retriever, benchmark):
    results = []
    for q in benchmark:
        hits = retriever.retrieve(q['query_text'], top_k=5)
        # Check if any Tier 1-2 result in top 5
        tier_ok = any(h['source_tier'] <= 2 for h in hits)
        # Check if correct crop in top 3
        crop_ok = any(h.get('crop') == q['expected_crop'] for h in hits[:3])
        results.append({'query': q['query_text'], 'tier_ok': tier_ok, 'crop_ok': crop_ok})
    pass_rate = sum(1 for r in results if r['tier_ok'] and r['crop_ok']) / len(results)
    print(f'Retrieval pass rate: {pass_rate:.1%}')
    assert pass_rate >= 0.80, f'Retrieval quality below threshold: {pass_rate:.1%}'
8. ON-DEVICE LLM CONSTRAINTS (Qwen3-1.7B)
⚠ Qwen3-1.7B is a 1.7 billion parameter model. It cannot reliably generate complex agricultural advisories. Its role on-device is strictly limited to language generation from pre-structured inputs.
8.1 What Qwen3-1.7B CAN Do On-Device
Generate advisory text from a pre-filled template with specific slots
Translate structured advisory from English template to Malayalam
Summarize a morning briefing from pre-computed risk scores
Generate simple 'What to check today' sentences from risk level + crop stage
8.2 What Qwen3-1.7B Must NOT Do On-Device
Generate disease diagnoses independently — use ONNX vision model for this
Provide pesticide recommendations — use cached knowledge templates only
Calculate yield estimates — use local rules engine
Access or reason about government schemes — use cached scheme data

9.2 Prompt Modification Rules
⚠ Do NOT modify the system prompts in this document without testing. LLM behavior changes unpredictably with wording changes. If you believe a prompt needs modification: (1) Test original prompt first. (2) Document why change is needed. (3) Test modified prompt on 20+ cases. (4) Compare results. Only then update this document.
